# Speech Coach frontend design spec

Every screen is built from this file. Angle: **drill-first**. A debater runs timed reps between rounds: one thumb, one glance, next rep. Numbers are big, chrome is minimal, nothing moves unless it carries information. Two agents building two screens without talking must produce siblings. If something is missing, use the closest existing token or class; never invent a parallel one or edit this file in a task.

## 1. Screens and navigation

| Screen | Route | Purpose |
|---|---|---|
| Onboarding | `#/onboarding` | First launch only: what is measured, audio is deleted after analysis, one button. |
| Practice | `#/practice` (default) | Talk on a timed topic or read a passage aloud, record, stop. Home. |
| Results | `#/results/:id` | A two-sentence headline, four metric cards with "vs last take" lines, the speech timeline, the highlighted transcript, one or two tips. |
| History | `#/history` | Sessions newest first with a status word, tap to reopen, delete with confirm. |
| Progress | `#/progress` | Metric switch, summary row, hand-rolled SVG line chart with the target band and the personal best. |

**Flow.** On boot, if `app.store.getFlag("onboarded")` is false the router opens Onboarding; its single button sets the flag and goes to Practice. Practice is home: the empty hash, the left nav item, where "Record again" returns. It opens on the Talk tab with "Your day" selected; the tab, the option and the topic stay as the speaker left them while the app is open. Stop uploads immediately (no submit step); on success the session is saved and the router goes to `#/results/<id>`. Results keeps an action bar stuck above the nav with "History" (`.btn--ghost`) and "Record again" (`.btn--primary`), or at the end of the page on a short or zoomed window; History rows open Results by id. The nav shows Practice, History, Progress; on Results no item is active. The nav is hidden on Onboarding and while the active Practice is `recording` or `uploading`, so a stray thumb cannot abandon a take.

Routing is hash-based in `app.js`. Exactly one `.screen` has `.screen--active`; the others carry the `hidden` attribute. A route to another screen, or to another session on Results, scrolls the window to the top once the new section is active; a hash that lands on the page already shown keeps the scroll. The tab title is the screen's h1, then " · Speech Coach" ("Results · Speech Coach"); Onboarding, whose h1 is the app's name, keeps "Speech Coach".

## 2. File layout and the `app` namespace

```
frontend/
  index.html          five <section class="screen">, <nav>, scripts in the order below,
                      one inline theme script in <head>
  styles.css          tokens, base, components, screens, one file
  app.js              creates window.app, hash router, boots on DOMContentLoaded
  ui.js               app.ui: el, renderState, clear, announce, formatClock, formatDate,
                      formatDay, icon, getTheme, applyTheme, setTheme, nextTheme
  store.js            app.store: IndexedDB sessions + flags + skill-path progress
  api.js              app.api.analyze
  passages.js         app.passages: [{id, kind, title, text, targetWpm: [lo, hi], source?,
                      format?, timeLimitSeconds?, topics?}], and app.passages.coldReads()
  delivery.js         app.delivery: the filler rules and the delivery report (analyze, classify)
  path.js             app.path: the skill path's units, levels and rules (order, evaluate,
                      unlocking, pickColdRead)
  tips.js             app.tips.select(report, options) -> up to two {id, text}
  pauses.js           app.pauses, human-owned (T08); agents never touch it
  screens/practice.js results.js history.js progress.js onboarding.js
  how.html            static "How we measure" page: each metric's rule, band and source
  sample-session.json one real take, loaded by Practice's "See a sample result"
  manifest.json  sw.js  icons/   (T10)
```

Script order: `app.js`, `ui.js`, `store.js`, `api.js`, `passages.js`, `delivery.js`, `path.js`, `tips.js`, `pauses.js`, then the five screens. Classic `<script>` tags, no modules, no build, no CDN. The list is fixed by `backend/tests/test_frontend_shell.py`, so a new helper lives in the module that owns its data, never in a new file. Every file is an IIFE assigning exactly one `app.<name>`; `window.app` is the only global. Each file opens with a two-to-four line comment saying what it owns. Transcript and user text never go through `innerHTML`; build nodes with `app.ui.el`, and SVG with `createElementNS`.

Contracts (exact names):

- `app.router.go(name, params)`, `app.router.current()`. A screen registers `app.screens[name] = { mount(root), show(params), hide() }`; `app.js` calls `mount` once at boot with its `<section id="screen-<name>" class="screen">`, then `show`/`hide` on each hash change. A module never touches DOM outside its `root`; shared data goes through `app.store` and route params.
- `app.store.save(session) -> Promise<id>`, `list()` newest first, `get(id)`, `remove(id)`, `getFlag(key)`, `setFlag(key, value)`. Session: `{id, createdAt, passageId, passageTitle, durationSeconds, metrics, transcript}`; `metrics` is the backend dict unchanged, `transcript` the backend word list `[{text, start, end}]`. Audio is never stored. Skill-path progress: `markLevelCleared(levelId, clearedAt?) -> Promise<{levelId, clearedAt}>` records an `app.path` level as cleared (`clearedAt` an ISO time, now unless given; a level cleared again keeps its first one) and `listClearedLevels()` lists the records in the order they were cleared. They live in the `pathProgress` store that database version 2 adds; the upgrade creates only that store, so saved sessions and flags stay. While a tab running an older version holds the database open, the upgrade waits for that tab to close, and every call fails at once with "Close other Speech Coach tabs to finish updating, then try again." rather than wait (boot then opens ungated); once the tab closes, the upgrade finishes and later calls go through.
- `app.passages`: `kind: "passage"` is read word for word and lists on the Read tab; `kind: "prompt"` is a topic to talk on and lists on the Talk tab. Every prompt has `timeLimitSeconds`. A prompt with `topics` shows one topic at a time, starting with the first, and New topic moves to the next one, wrapping; its `text` repeats `topics[0]` so every entry has text. The `free-talk` id is titled "Your day"; the id stays so saved takes still find their band. Prompts come first, because Practice opens on the first entry's tab with that entry selected. `app.passages.coldReads()` returns a new array of the cold reads for the skill path's cold-read mode: `kind: "passage"` entries with `coldRead: true` and a 140 to 160 wpm band, each 120 to 200 words of original debate-style argument with no digits, symbols or quotation marks and none of `app.delivery.HABIT_WORDS`, so a take read as written shows no misread and no filler. They are not entries of `app.passages`, so the Read tab never lists them.
- `app.delivery.analyze(words, metrics) -> report` re-scores a stored take from its words, so every saved session uses today's rules: `kinds` (`"hesitation"`, `"habit"` or null per word), `fillers` (`{index, text, kind, start, end}`, "you know" is one event), `fillerCount`, `hesitationCount`, `habitCounts`, `topHabit` (`{text, count}` or null), `speechStart` (the first word's start, null without words), `speakingSeconds`, `wordsPerMinute` (hesitation sounds are not words), `fillersPerMinute`, `pauses` (`{at, length, midSentence}`), `midSentencePauseCount`, `longestMidSentencePause`, `cleanStretch` (`{start, end, seconds}` or null), `repeatCount` and `restarts` (`{at, text, secondCopy}` per backend repeat, `secondCopy` the indexes of the words that say the phrase again), `followedScript` (true when `metrics` has a script block: the backend found the take follows the script it was sent; false for free talk and for a take that strays from its script, which the backend scores as free talk), `misreads` (`{at, word, said, wordIndex}` per `metrics.script.misread` entry, `wordIndex` the transcript word that said it, -1 when none does) and `skips` (`{at, word}` per `metrics.script.skipped` entry); both are empty for a take without a script block. Every time in the report is in recording seconds, the clock the tips print. A session with no words falls back to the backend tallies. Results, tips and Progress read this report; `metrics` stays the backend dict unchanged.
- `app.path` (docs/PLAN.md T42) is the skill path. `UNITS` holds four units `{id, title, tags, levels}`, `restarts`, `fillers`, `long-pauses` and `pace` in that order (the order of `backend/advice/select.py` MEASURED_SKILLS; `tags` are the research library's). Each has five levels `{id, unit, number, mode, prompt, durationSeconds, pass, passageId}`, the id `"<unit>-<number>"`, each a little harder than the one before. A unit trains with one mode (`MODE_TITLES` names them): Restarts with `coldRead` (`pass.maxSlips` restarts and misreads in all; `passageId` null), Fillers with `suddenDeath` (`pass.runSeconds` from the first word to the first filler or restart, talked on `free-talk`), Long pauses with `cleanStretch` (`pass.stretchSeconds`, talked on `impromptu`) and Pace with `speedLadder` (`pass.wpm` give or take `pass.toleranceWpm`, at most `pass.maxRestarts`, read from `rebuttal-uniforms`). `evaluate(level, report) -> {passed, detail}` scores a take's `app.delivery` report, `detail` the sentence the speaker reads; a reading take (`coldRead`, `speedLadder`) fails when `report.followedScript` is false ("This take did not follow the passage. Read it as written to clear this level.") or when it leaves out more than 8 script words in one place. `order(history)` returns the units weakest first, each unit's distance from target averaged over the five latest takes, each take weighted by its speaking minutes, as select.py's `weakest_skills` ranks one take, ties and an empty history keeping the order of `UNITS`. `isUnlocked(level, cleared)`, `statusOf(level, cleared) -> "cleared" | "current" | "locked"` and `currentLevel(unit, cleared)` read `app.store.listClearedLevels()`: a unit's first level is always open and level n + 1 opens once level n is cleared. `pickColdRead(history, random)` returns a cold read no take in `history` has read, drawn with `random` (a function such as `Math.random`), or once all are read the one read longest ago. `levelById(id)`. Pure: no DOM, no store, randomness only from the source passed in.
- `app.screens.results` also exports pure helpers that touch no DOM and no `app.ui`: `summarize(session)` (shared with History and Progress; its `timeUsed` is `{seconds, limitSeconds}` for a timed option, else null), `buildTranscriptPlan(words, pauses, restartWords, scriptSlips)` (a word whose index is in `restartWords` gets `restart: true`; with the report's `{misreads, skips}`, a misread word gets `misread`, the script word, and each skip is a `{type: "skip", text}` item, or for more than 8 in one place one `{type: "skip", text, count}` run), `headlineFor(summary, previousSummary) -> {strength, focus}`, `compareWithPrevious(summary, previousSummary) -> null | [four {direction, text} or null, in card order]` `timelineSegments(report) -> null | {start, seconds, fillers, pauses, restarts, cleanStretch}` and `isSample(session)`, true when `passageTitle` starts with "Sample: " (the bundled take "See a sample result" saves: History lists it, but no comparison and nothing on Progress uses it). `app.screens.history.statusFor(summary) -> {text, tone} | null`: null unless `summary.wpm` is above 0; pace is checked only against a two-number `summary.target`, both ends inside; fillers miss above 3 a minute; misses join with " · ", pace first; "On target" has tone `"ok"`, anything else `"warn"`. `app.screens.progress` exports `series` (samples left out), `scale` and `summaryFor(values, key, targets) -> {latest, best, bestIndex, average, change}`, which reads one metric's values oldest first with each take's `[lo, hi]` pace band; a null value marks a take with nothing measured, and `bestIndex` is -1 when no take can be best.
- `app.api.analyze(blob, contentType) -> Promise<{transcript, metrics}>`; rejects with an `Error` whose `.kind` is `"network" | "too_short" | "provider" | "unknown"` and whose `.message` is the matching string in section 8. A request still open three minutes after it starts (`ANALYZE_TIMEOUT_MS`, while sending or while reading the reply) is aborted through an `AbortController` and rejects as `"network"`; the backend gives each provider call two minutes, so its own `"provider"` error comes first. Without `AbortController` or the timers there is no deadline.
- `app.ui.el(tag, attrs, children)`; `renderState(root, {kind, title, body, actionLabel, onAction, icon, secondaryLabel, onSecondary})`, kind `"empty" | "error" | "loading"`, icon `"mic" | "chart" | "search"`; `clear(root)`; `announce(text)` writes the `.sr-only` live region; `formatClock(seconds) -> "1:05"`; `formatDate(iso) -> "Oct 9, 10:21 PM"`; `formatDay(iso) -> "Oct 9"`; `icon(name, size = 20) -> <svg> | null` (null for an unknown name), a 24-unit icon in `currentColor`, `aria-hidden="true"`, `data-icon` set to its name, built on each call; the triangles and half of `contrast` are filled, the rest are 2-unit strokes: `mic`, `chart`, `search`, `alert`, `trash`, `check`, `arrow-right`, `refresh`, `triangle-up`, `triangle-down`, `dash`, `contrast`, `moon`, `sun`. Theme: `getTheme() -> "auto" | "dark" | "light"` ("auto" when nothing is saved or storage is blocked), `applyTheme(choice)` sets `data-theme` on `<html>` (none for auto) and points both theme-color metas at that theme's `--bg`, `setTheme(choice)` saves then applies, `nextTheme(choice)` cycles auto, dark, light. The theme is the one setting kept in `localStorage` (key `speech-coach-theme`, every access in try/catch), because it is read synchronously; `app.js` applies it at boot, before any screen mounts. One inline script in `<head>`, right after the stylesheet and wrapped so it adds no global, sets `data-theme` from a saved "dark" or "light" before the first paint (Auto, an unknown value or blocked storage sets nothing); it has no `src`, so the fixed script list leaves it out. On a slow load only the theme-color metas follow the device scheme until `app.js` applies the theme at boot. Sessions and flags stay in IndexedDB.
- Practice keeps its state in one string, `app.screens.practice.state`; one `render(state)` function is the only code that touches that screen's DOM, apart from the clock and its bar (the timer paints them while a take runs, and the clock goes back to 0:00 when a take is let go), a focused chip scrolling into view, and the theme toggle, which repaints itself.

## 3. Layout and spacing

Single column, phone first. `main` is `max-width: var(--col-max); margin: 0 auto; padding: var(--s-4) var(--s-4) calc(var(--nav-h) + var(--s-5) + env(safe-area-inset-bottom))`. Never horizontal scroll at 320px; transcript uses `overflow-wrap: anywhere`.

```
--s-1: 4px;  --s-2: 8px;  --s-3: 12px; --s-4: 16px;
--s-5: 24px; --s-6: 32px; --s-7: 48px;
--r-card: 12px; --r-btn: 10px; --r-tok: 4px; --r-chip: 999px;
--nav-h: 56px; --col-max: 640px;
```

Only these values for margin, padding and gap. Rhythm: section gap `--s-6`, card gap `--s-3`, label-to-value `--s-1`. Every screen's content starts `--s-3` under its title (`.screen > h1`, and Practice's header), so the same control never shifts between tabs; on Results the meta line sits `--s-1` under the h1 as its subtitle (the title keeps `--s-3` over Session not found), the headline `--s-5` below it and the grid `--s-6` below the headline. No shadows; separation is `--surface` on `--bg` plus a 1px `--border`. `.metric-grid` is `display: grid; grid-template-columns: 1fr 1fr; column-gap: var(--s-3)`, so the four cards sit 2 x 2 inside the column from 240px up; the second row takes `margin-top: var(--s-3)` instead of a row gap, which would also open between the cards' subgrid rows. Under 240px (200% zoom on a phone) the cards stack, each `--s-3` below the one before.

**Practice fits one screen.** Its body, top to bottom: `.segmented` (Talk or Read), `.chip-row`, `.passage-card`, `.practice__timer`, `.btn-record`, `.btn-record__label`, `.practice__hint`, `.practice__state`. The active Practice section is a flex column at least as tall as the viewport minus `main`'s padding, so the record zone sits in the bottom thumb zone above the nav at 375 x 667 and 320 x 568 without scrolling. The topic or passage card takes the height left over (`flex: 1 1 0; min-height: 120px`) and scrolls inside; every other child keeps its size (`flex: none`). In the record zone `--s-3` sits above the timer and the record button, `--s-2` above the limit bar and `--s-1` above the label and the hint. While a take records or uploads the nav is hidden: `main`'s bottom padding drops the nav's share, the column grows by `--nav-h` and the card takes that room, so the record button moves down when a take starts. Under `max-height: 600px` the card's floor is 148px (its title, its target and two full lines above the fade), the record button shrinks to 72px, the gaps above the timer and the record button drop to `--s-2` and above the limit bar to `--s-1`, the hint text hides, and an error block takes the card's place; narrower than 480px as well, the whole hint hides, "See a sample result" included. At 200% zoom or in landscape the column grows and the page scrolls.

**Script box.** On Talk, `details.practice__script` closes the `.practice__hint` row, after "See a sample result", so the body's list above is unchanged and the closed box adds no row: at 375 x 667 the two share one line, and on a narrower screen the summary wraps inside its own half. Under `max-height: 600px` and narrower than 480px it hides with the whole hint, so 320 x 568 still fits. Open, it takes the hint's full width, the column grows and the page scrolls.

**Wide screens.** The nav's items sit in the same centered column as the content. The Results action bar spans the column and parks its two buttons at the column's end; its primary button caps at 320px.

## 5. Type scale

`font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. Every number uses `font-variant-numeric: tabular-nums`; Results sets it on `#screen-results`, so hints, the headline, legends and tips are tabular too.

```
--fs-metric:        40px / 1.0 / 700   metric card value, the Practice timer
--fs-metric-narrow: 32px / 1.0 / 700   metric card value under 360px
--fs-h1:            24px / 1.2 / 700   screen title (one per screen)
--fs-h2:            18px / 1.3 / 600   section title, passage title, Progress summary value (at 700)
--fs-body:          16px / 1.5 / 400   transcript, passage text, headline, body
--fs-small:         14px / 1.4 / 500   labels, chips, segments, hints, row text
--fs-micro:         12px / 1.3 / 500   nav labels, timestamps, axis labels, delta lines, legends
```

Body never goes below 16px. Everything is sentence case; no label is uppercased or letter-spaced. Metric labels are short: "Pace", "Fillers", "Pauses", "Clean stretch". Labels wrap; they never truncate.

## 6. Component inventory

Class names are exact (`block__part`, `block--modifier`).

**Buttons** `.btn`: `min-height: 48px; padding: 0 var(--s-5); border-radius: var(--r-btn); font: 600 var(--fs-body); display: inline-flex; align-items: center; justify-content: center; gap: var(--s-2)`. Variants: `.btn--primary` (accent bg, on-accent text; one per screen), `.btn--secondary` (surface bg, text color, 1px border), `.btn--ghost` (transparent, accent text), `.btn--danger` (transparent, `--record-text` text and a 1px `--record` border; Delete only), `.btn--block` (width 100%). Disabled: `opacity: .5`, ignores clicks. `.icon-btn`: a 44 x 44 transparent button holding one 20px `app.ui.icon`, `--muted`, with an `aria-label`.

**Header** `.screen__header` (Practice): the `h1` and, at the right, `.wordmark` (a 16px mic mark and "Speech Coach", small, 500, muted, no-wrap) followed by `button.icon-btn.theme-toggle`. The toggle shows the current choice, `contrast` for Auto, `moon` for Dark, `sun` for Light, and each tap moves to the next. Its `aria-label` names the choice and the next one: "Theme: Auto. Switch to dark." Its 44px hit area reaches `--s-2` past the header's top, bottom and right edges, so the row stays as tall as the `h1`. The row wraps, so at 200% zoom the wordmark and the toggle drop under the `h1`.

**Segmented control** `.segmented` (Practice mode, Progress metric): `role="group"` with an `aria-label`, one row of equal `button.segmented__option` (`aria-pressed`) in a `--surface` container with a 1px border, `--r-btn` radius and `--s-1` inner padding. Options are 44px tall, small, `--muted`, with corners of `calc(var(--r-btn) - var(--s-1))` so they nest inside the container; `.segmented__option--selected` is accent fill with on-accent text. Practice: "Talk" and "Read" (`aria-label="Practice mode"`), disabled outside idle, when only the unselected option dims to .5. Progress: "Pace", "Fillers", "Pauses", "Clean" (`aria-label="Chart metric"`), which fits 288px; under 300px (200% zoom) the options form two rows of two.

**Chips** `.chip`: `<button>`, `min-height: 44px; padding: 0 var(--s-4); border-radius: var(--r-chip); font: 500 var(--fs-small)`, surface bg, 1px border. `.chip--selected`: accent bg, on-accent text, `aria-pressed="true"`. `.chip-row`: horizontal flex, `gap: var(--s-2)`, `overflow-x: auto`. Practice's chips are the options of the current tab; a timed option reads "Your day 1:00". Its row bleeds to the screen edges (a negative inline margin of `--s-4` with matching padding) and fades out over its last `--s-6`, with `--s-6` of end padding so the last chip can scroll clear. With a mouse (`(hover: hover) and (pointer: fine)`) in a window at least 640px wide and 750px tall, the row wraps inside the column instead, with no bleed, fade or end padding, since a wheel cannot scroll it sideways; Read's six chips take three lines there, and every state still fits above the nav. Touch screens and smaller mouse windows keep the swipe row, which Tab, Shift+wheel and a trackpad still scroll. Each entry's chip is built once; the other tab's chips carry `hidden`. While the chips are disabled (recording, uploading, error), the selected chip keeps full contrast and the others dim to .5. `--s-2` of block padding, pulled back by matching negative margins, keeps focus rings clear of the row's clip, and a chip that takes focus scrolls into view inside the row's scroll padding, so its ring never sits under the fade.

|---|---|---|---|---|---|

Mic permission is requested on the first record tap, never on load. Stopping under 5 s goes straight to `error`; nothing is uploaded. A take that is let go (saved, dropped with "Record a new take" or by a backend 400, or left behind by leaving the screen) puts the clock back to 0:00, and the bar is empty in idle on every path.
